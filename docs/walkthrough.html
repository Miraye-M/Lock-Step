Lockstep carries a vulnerability fix from ACC to ACS, with evidence at every step.

A resolved ACC Jira ticket goes in. A review-ready ACS pull request comes out, backed by a reproduced failure, independent reviews, a built artifact, acceptance test results and a human-approved plan. Specialist agents propose. A deterministic worker verifies, gates and records. A human sets the pace.

Problem and aim

What goes wrong today

Two related codebases share a flaw. ACC fixes it and closes the ticket. Someone must now find the real fix commit, decide whether ACS is affected, adapt the patch, prove the hole is closed, get the build and acceptance run done, and open a PR with the right people signed off. Every ticket repeats the same questions. The evidence ends up in heads and chat threads, and an AI assistant that says "ported, tests pass" adds a claim, not proof.

What Lockstep guarantees

  • No file is written until the vulnerability fails in ACS and a human has approved one specific plan digest.
  • Every claim is checked against something the backend can see: Git objects, exit codes, output patterns, job identities, digests.
  • Reviews, QA and jobs bind to the exact source tree and commit. Change the tree and they are revoked together.
  • Side effects are recorded as intent first and reconciled by idempotency key, never replayed blindly.
  • The output is a PR with the full audit trail. Merge and release stay with your process.

Native Copilot handoff

How a specialist is asked, without the worker launching a model

With agent: vscode the worker never spawns a model process. It writes a task record, parks the run, and the orchestrator in VS Code dispatches the named specialist in a fresh isolated context. The reply comes back through a validated, idempotent submission. Only the worker consumes it.

Evidence binding

Nothing is trusted because an agent said it

Failure handling

Every stop is explicit

Run statusWhyWhat a human doesWhat the tool refuses
pausedA gate failed, a specialist listed blockers or the plan needs approval. required_action names the condition.Fix the cause, then resume. At approval, approve with the exact digest.Resume cannot approve a plan, reset the two-attempt repair budget or erase a job ID.
waitingA Jenkins or AFT job is queued or running. One build slot; another run ready to build is held, not paused.Nothing. status --summary shows who holds the slot.No second build is submitted. A failed or timed-out job pauses the run and is retained for inspection.

Adoption

Integrating Lockstep in a team

Decide the operating model

An operator runs the worker under a scoped service account on a build box or container. A reviewer from product security approves plans and accepts PRs. The orchestrator is whoever drives it from VS Code or the CLI. The worker needs dedicated clones of ACC and ACS.

Create and configure a control project

Run specify remediation init --no-demo --agent vscode. Fill in repository paths, target branch, test commands, the regression command and its failure pattern, named local checks with passing-test patterns, required acceptance suites and environment, timeouts and the environment allowlist your test runner needs.

Build one connector

Write a stdio MCP server implementing the ten operations (ticket read, ticket ensure, fix read, push, PR, build submit and status, AFT submit and status, effect lookup) with idempotency-key lookup. Map them under servers and tools. Secrets travel as named environment variables and never reach agents, tests or reports. Run doctor until it is clean.

Pilot, measure, widen

Start with one ACS repository and low-risk tickets. Track time from ACC resolution to ACS PR, pause reasons and repair attempts per ticket. Tighten patterns and checks before adding repositories.

Say this up front

  • Single-parent fix commits, one build at a time, Copilot only. Checks run on the host OS.
  • Agent profiles and path guards are defense in depth, not a sandbox. Run the worker with least privilege.
  • Human accountability stays: plan approval and PR acceptance are recorded decisions on specific digests. The checklist in every report is unchecked on purpose.
